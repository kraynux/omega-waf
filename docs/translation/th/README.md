**Omega-Waf** คือสคริปต์ Lua เพียงไฟล์เดียว (`omega-waf.lua`) ที่ไม่มี dependency ภายนอก ออกแบบมาให้เว็บเซิร์ฟเวอร์ที่รองรับ `mod_magnet` เรียกใช้กับทุกคำขอ HTTP (lighttpd แบบเนทีฟ หรือ omega-serv ผ่านสะพานความเข้ากันได้ `magnet`) สคริปต์จะตรวจสอบพาธ คำขอ และเนื้อหาของคำขอเมื่อเป็น POST เพื่อค้นหาซิกเนเจอร์การโจมตีที่รู้จัก (SQL injection, XSS, command injection, path traversal) ใช้การจำกัดอัตรา (rate limiting) จัดการรายการบล็อกแบบถาวรพร้อมการยกระดับเป็นขั้น และบันทึกทุกการตัดสินใจลงล็อก

ไม่มีการติดตั้งในความหมายแบบดั้งเดิม: มีเพียงไฟล์เดียวที่ต้องวางไว้ อ้างอิงจากการกำหนดค่าของเซิร์ฟเวอร์ แค่นั้นเอง

## ภาพรวม

### เป้าหมาย

- กรองคำขอที่เป็นอันตรายให้ใกล้เซิร์ฟเวอร์ที่สุด ก่อนที่คำขอจะไปถึงแอปพลิเคชันที่ให้บริการ
- คงความเป็นไฟล์เดียวที่อ่านเข้าใจง่าย ไม่มี dependency ภายนอก และไม่มีขั้นตอนคอมไพล์
- ไม่ทำให้เว็บเซิร์ฟเวอร์ล่มเด็ดขาด: ข้อผิดพลาดภายในสคริปต์ทุกกรณีจะถูกดักจับและบันทึกลงล็อกแทนที่จะถูกส่งต่อ
- จำกัดค่าใช้จ่าย CPU/หน่วยความจำต่อคำขอ (แคชตามเวลา อ่านเนื้อหาเป็นชิ้น ๆ จำกัดความลึกของการถอดรหัส)
- ให้การยกระดับเป็นขั้น (คำเตือนแล้วจึงแบน) แทนการแบนทันทีตั้งแต่เหตุการณ์เล็กน้อยครั้งแรก

### สิ่งที่ Omega-Waf ทำ

- บล็อกที่อยู่ IP ที่ถูกแบนแล้ว (รายการบล็อกแบบถาวรบนดิสก์) โดยมีข้อยกเว้นสำหรับพาธที่อนุญาตไว้อย่างชัดเจน (CSS ของหน้าแสดงข้อผิดพลาด ฯลฯ)
- เฝ้าติดตามชุดพาธที่อ่อนไหว (`.git`, `.env`, `wp-admin`, `phpmyadmin`, `.DS_Store` ฯลฯ) และตอบกลับด้วยหน้าคำเตือน HTML หรือแบนทันทีเมื่อมีการกระทำซ้ำ
- ตรวจจับ User-Agent ที่รู้จักว่าเป็นเครื่องมือสแกนหรือบอตที่ไม่พึงประสงค์ (sqlmap, nmap, nikto, dirbuster, crawler ทั่วไป...)
- ใช้การจำกัดอัตราแบบรวมต่อ IP ครอบคลุมทุกเส้นทาง
- ใช้นโยบายเฉพาะที่ผ่อนปรนกว่าบนเส้นทางของเครื่องมือค้นหา SearXNG (หลีกเลี่ยงผลบวกลวงกับคำค้นหาที่ชอบธรรมซึ่งมีคีย์เวิร์ดที่ดูคล้ายการโจมตี)
- ตรวจสอบพาธและ query string (SQLi, XSS, path traversal, ไบต์ NUL)
- ตรวจสอบเนื้อหาของคำขอ POST (SQLi, XSS, command injection, path traversal) ด้วยระบบคะแนนสะสม
- จัดการการยกระดับเป็นขั้น: พฤติกรรมน่าสงสัยที่เกิดขึ้นครั้งเดียวจะทำให้เกิดการแจ้งเตือนหรือการปฏิเสธเฉพาะครั้ง; การกระทำซ้ำภายในกรอบเวลาจะทำให้ถูกแบนถาวร
- บันทึกทุกการตัดสินใจ (การแจ้งเตือน การเพิ่มเข้ารายการบล็อก) ลงล็อกในรูปแบบข้อความหรือ JSON
- ทำงานได้ทั้งใน lighttpd แบบเนทีฟ (พาธกำหนดตายตัวในโค้ด) และเมื่อถูกฉีดเข้าไปใน omega-serv (พาธได้รับแบบไดนามิกจากการกำหนดค่าของเซิร์ฟเวอร์)

### สิ่งที่สคริปต์ไม่ทำ

- ไม่ได้แทนที่ WAF เฉพาะทางระดับองค์กร (ModSecurity, Coraza, WAF บนคลาวด์): ซิกเนเจอร์ถูกออกแบบให้เรียบง่ายโดยเจตนา (การจับคู่รูปแบบของ Lua ไม่ใช่เอนจินกฎ PCRE ที่แท้จริง)
- ไม่วิเคราะห์ส่วนหัว HTTP ทีละรายการนอกเหนือจาก User-Agent
- ไม่ถอดรหัสเนื้อหาแบบ multipart/form-data หรือเนื้อหาที่บีบอัด (gzip) — การตรวจสอบทำกับข้อความดิบที่ได้รับ
- ไม่ตรวจสอบเนื้อหาของคำขออื่นนอกจาก POST
- ไม่ตรวจจับ command injection บนพาธของ URL (เป็นการเลือกโดยเจตนา ดู [ข้อจำกัดที่ทราบ](#ข้อจำกัดที่ทราบและสิ่งที่อยู่นอกขอบเขต))
- ไม่มีอินเทอร์เฟซสำหรับผู้ดูแล: การกำหนดค่าทำได้โดยแก้ไขตัวแปรที่ส่วนต้นของไฟล์ ส่วนรายการบล็อกและ whitelist ทำผ่านไฟล์ข้อความธรรมดา
- ไม่จัดการการหมุนเวียน (rotation) ล็อกของตัวเอง

### คำเตือนการใช้งาน

ซิกเนเจอร์ที่ให้มามุ่งเป้าไปที่ตระกูลการโจมตีที่พบบ่อย แต่ไม่ได้เป็นการป้องกันที่ครอบคลุมทั้งหมด เกณฑ์คะแนนการตรวจจับที่ต่ำเกินไปบนเว็บไซต์ที่มีทราฟฟิกผิดปกติ (การค้นหาเชิงเทคนิค เอกสารที่มีคำสั่งเชลล์ ฯลฯ) อาจทำให้เกิดผลบวกลวง — ปรับ `waf_score_threshold` และ whitelist ของพาธให้เหมาะสม ทดสอบการเปลี่ยนแปลงซิกเนเจอร์หรือเกณฑ์ในสภาพแวดล้อมที่ไม่สำคัญเสมอก่อนนำไปใช้งานจริง

## การติดตั้ง

### สิ่งที่ต้องมี

- เว็บเซิร์ฟเวอร์ที่มีอินเทอร์เฟซที่รองรับ `mod_magnet`:
  - **lighttpd** ที่เปิดใช้งานโมดูล `mod_magnet` (`server.modules += ("mod_magnet")`) หรือ
  - **omega-serv** ที่ติดตั้งส่วนเสริม (extra) `magnet` แล้ว (dependency `lupa` — ดูด้านล่างและคู่มือ omega-serv หัวข้อ WAF Magnet)
- ตัวแปลภาษา Lua แบบฝังตัวที่โฮสต์จัดให้ (lighttpd ฝัง Lua ของตัวเอง; omega-serv ฝัง `lupa` ทั้งสองกรณีไม่ต้องมีตัวแปลภาษา `lua` ของระบบ — `lupa` แจกจ่ายเป็น wheel ที่คอมไพล์ไว้ล่วงหน้าสำหรับสถาปัตยกรรม/เวอร์ชัน Python ที่ใช้กันทั่วไปทั้งหมด ไม่ต้องคอมไพล์ในเครื่องและไม่ต้องใช้ไฟล์ header ของ Lua ในระบบ)

#### การติดตั้งส่วนเสริม `magnet` ของ omega-serv

**ติดตั้งจาก `.venv` ที่ `omega-serv/install.sh` สร้างไว้แล้วเสมอ ห้ามใช้ `pip` ของระบบ** — ในบางดิสทริบิวชัน (โดยเฉพาะ Arch Linux) คำสั่ง `pip` เปล่า ๆ ไม่มีอยู่ (มีเพียงแพ็กเกจ `python-pip` ที่ติดตั้งให้ และไม่ได้ติดตั้งเป็นค่าเริ่มต้นเสมอไป) หรือปฏิเสธการติดตั้งใด ๆ นอกสภาพแวดล้อมเสมือน (`error: externally-managed-environment`, PEP 668):

```bash
cd /path/to/omega-serv

# ตัวเลือก A - venv เปิดใช้งานอยู่แล้วในเชลล์ปัจจุบัน
source .venv/bin/activate
pip install -e ".[magnet]"

# ตัวเลือก B - โดยไม่เปิดใช้งาน venv (พกพาได้มากที่สุด: ไม่ขึ้นกับว่า
# มี 'pip' อยู่บน PATH ของระบบหรือไม่ เพราะ python ของ
# venv มี pip ของตัวเองมาด้วยเสมอ)
.venv/bin/python -m pip install -e ".[magnet]"
```

หากยังไม่ได้รัน `install.sh` (ไม่มี `.venv/`) ให้รันก่อน — สคริปต์จะสร้างสภาพแวดล้อมเสมือนและติดตั้ง omega-serv ลงไปให้แล้ว จากนั้นเหลือเพียงเพิ่มส่วนเสริม `magnet` (ไม่บังคับ) ด้วยคำสั่งใดคำสั่งหนึ่งจากสองคำสั่งด้านบน

### การนำไปใช้งาน

1. คัดลอก `omega-waf.lua` ไปยังตำแหน่งที่เซิร์ฟเวอร์อ่านได้ (เช่น `secure/waf/scripts/omega-waf.lua` สำหรับโครงสร้างไดเรกทอรีแบบ omega-serv หรือพาธใดก็ได้สำหรับ lighttpd แบบเนทีฟ)
2. สร้างไดเรกทอรี/ไฟล์ที่ต้องใช้:
   - **omega-serv**: ไม่ต้องทำอะไร เซิร์ฟเวอร์สร้างโฟลเดอร์เองเมื่อเริ่มทำงาน (รวมถึง `var/lib/waf/` ที่ใช้ร่วมกับบัญชีของบริการ)
   - **lighttpd แบบเนทีฟ**: ก่อนอื่นให้แทนที่ 5 พาธด้วยพาธแบบสัมบูรณ์ (ดู [พาธใน lighttpd แบบเนทีฟ](#พาธใน-lighttpd-แบบเนทีฟ)) แล้วสร้างโฟลเดอร์และทำให้บัญชีของ lighttpd เขียนได้ (`www-data` บน Debian/Ubuntu, `http` บน Arch, `lighttpd` บน Fedora/Alpine):
     ```bash
     sudo install -d -o www-data -g www-data -m 750 /var/lib/lighttpd/waf /var/log/lighttpd /var/cache/lighttpd
     sudo install -d -m 755 /var/lib/lighttpd/waf/magnet-rules.d
     sudo -u www-data touch /var/lib/lighttpd/waf/magnet-blocklist.txt
     ```
3. อ้างอิงสคริปต์จากการกำหนดค่าของเซิร์ฟเวอร์:
   - **lighttpd**:
     ```
     magnet.attract-physical-path-to = ( "/path/to/omega-waf.lua" )
     ```
   - **omega-serv**: เปิดใช้งาน WAF Magnet จากหน้าจอ TUI เฉพาะ (ความปลอดภัยเชิงรุก → WAF → Magnet) ซึ่งชี้ไปยังสคริปต์และฉีดตาราง `omega_magnet_paths` ให้อัตโนมัติ (ดู [ความเข้ากันได้](#ความเข้ากันได้))
4. รีสตาร์ต (ไม่ใช่รีโหลด — การรีโหลดไม่เคยโหลดสคริปต์ Lua ที่อยู่ในหน่วยความจำถาวรแล้วใหม่) เซิร์ฟเวอร์ที่เกี่ยวข้อง

## การกำหนดค่า

ตัวเลือกทั้งหมดตั้งค่าได้โดยแก้ไขตัวแปร local ที่ส่วนต้นของไฟล์โดยตรง (ส่วน `CONFIGURATION` บรรทัดประมาณ 24-70) ไม่มีไฟล์กำหนดค่าแยกต่างหาก

| ตัวแปร | บทบาท | ค่าเริ่มต้น |
|---|---|---|
| `blocklist_file` | ไฟล์ข้อความของ IP ที่ถูกแบนถาวร (หนึ่ง IP ต่อบรรทัด, `#` สำหรับความคิดเห็น) — สคริปต์เป็นผู้ **เขียน** | `var/lib/waf/magnet-blocklist.txt` |
| `waf_rules_dir` | โฟลเดอร์ของกฎภายนอก (มี `whitelist_paths.txt`) | `secure/waf/magnet-rules.d/` |
| `alerts_log` | ล็อกการแจ้งเตือน (การตรวจจับ การปฏิเสธ การเกินขีดจำกัด) | `var/log/waf-magnet-alerts.log` |
| `blocklist_log` | ล็อกเฉพาะสำหรับการเพิ่มเข้ารายการบล็อก | `var/log/waf-magnet-blocklist.log` |
| `rate_store_file` | ไฟล์จัดเก็บถาวรของตัวนับ (rate limit / การกระทำซ้ำ) ในรูปแบบตาราง Lua | `var/cache/waf-magnet-rate_store.lua` |
| `enable_body_inspection` | เปิดการตรวจสอบเนื้อหาของคำขอ POST | `true` |
| `enable_rate_limit` | เปิดการจำกัดอัตรา (แบบรวม + SearXNG) | `true` |
| `enable_auto_block` | อนุญาตให้เพิ่มเข้ารายการบล็อกโดยอัตโนมัติ | `true` |
| `never_auto_block` | เครือข่ายที่ **ไม่เคย** ถูกแบนอัตโนมัติ (คำขอยังคงถูกปฏิเสธและบันทึกลงล็อก เพียงแต่ไม่แบน); ภายใต้ omega-serv รายการที่เซิร์ฟเวอร์ฉีดเข้ามา (`omega_never_auto_block`) มีความสำคัญเหนือกว่าเสมอ | โฮสต์ในเครื่อง, Tailscale, เครือข่ายในพื้นที่ |
| `use_json_logs` | สลับล็อกการแจ้งเตือนเป็น JSON (มิฉะนั้นเป็นข้อความที่อ่านได้) | `false` |
| `waf_score_threshold` | คะแนนสะสมขั้นต่ำที่ทำให้คำขอ POST ถูกปฏิเสธ | `5` |
| `body_max_inspect` | ขนาดสูงสุดของเนื้อหาที่ถูกตรวจสอบ (ไบต์) | `65536` (64 KB) |
| `chunk_size` | ขนาดของชิ้นที่ใช้อ่านเนื้อหา | `8192` (8 KB) |
| `global_rate_max_req` / `global_rate_window` | โควตาและกรอบเวลา (วินาที) ของการจำกัดอัตราแบบรวมต่อ IP | `60` คำขอ / `60` วินาที |
| `searx_rate_max_req` / `searx_rate_window` | โควตาและกรอบเวลา (วินาที) ของการจำกัดอัตราเฉพาะเส้นทาง SearXNG | `40` คำขอ / `60` วินาที |
| `searx_max_query_len` | ขนาดสูงสุดของ query string ที่ยอมรับบนเส้นทาง SearXNG | `4096` อักขระ |
| `suspicious_threshold` | จำนวนครั้งที่น่าสงสัยก่อนถูกแบนถาวร | `3` |
| `suspicious_window` | กรอบเวลาเลื่อน (วินาที) ที่ใช้นับครั้งที่น่าสงสัย | `300` (5 นาที) |
| `blocklist_refresh_interval` | ช่วงเวลา (วินาที) ในการอ่านไฟล์รายการบล็อกใหม่ | `5` |
| `whitelist_refresh_interval` | ช่วงเวลา (วินาที) ในการอ่าน whitelist ของพาธใหม่ | `15` |

ภายใต้ omega-serv พาธ 5 รายการแรก (`blocklist_file`, `waf_rules_dir`, `alerts_log`, `blocklist_log`, `rate_store_file`) จะถูกแทนที่โดยอัตโนมัติด้วยพาธที่กำหนดไว้ในหน้าจอ WAF Magnet (ตารางส่วนกลาง `omega_magnet_paths` ที่ถูกฉีดก่อนการทำงาน) — ค่าที่กำหนดตายตัวด้านบนจะใช้เป็นค่าสำรองเฉพาะเมื่อไม่มีตารางนี้เท่านั้น

> ℹ️ **การเปลี่ยนแปลงเมื่อ 2026-10-18**: `blocklist_file` ย้ายจาก `secure/waf/magnet-blocklist.txt` ไปที่ `var/lib/waf/magnet-blocklist.txt` สคริปต์ **เขียน** ลงไฟล์นี้ทุกครั้งที่แบน และบริการ systemd ของ omega-serv เขียนได้เฉพาะภายใต้ `var/` เท่านั้น: เมื่อใช้ตำแหน่งเดิม การแบนอัตโนมัติจึงไม่เคยถูกบันทึกเลย โดยไม่มีข้อความใด ๆ omega-serv จะนำไฟล์เดิมมาใช้เพียงครั้งเดียวเมื่อเริ่มทำงาน (ไฟล์เดิมยังคงอยู่เป็นสำรอง); พาธที่กำหนดเองในหน้าจอ WAF Magnet จะไม่ถูกเปลี่ยนแปลงเลย

### พาธใน lighttpd แบบเนทีฟ

> ⚠️ **ค่าเริ่มต้นทั้ง 5 ค่านี้อิงตามแบบแผนโฟลเดอร์ของ omega-serv** (`var/lib/waf/...`, `secure/waf/...`, `var/log/...`, `var/cache/...` เป็นพาธแบบสัมพัทธ์ที่อ้างอิงจากไดเรกทอรีทำงานแบบโปรเจกต์) — จึงไม่ได้เป็นกลาง ใน **lighttpd แบบเนทีฟ** ซึ่งไม่มีแบบแผนโฟลเดอร์ที่เทียบเท่า พาธสัมพัทธ์เหล่านี้จะอ้างอิงจากไดเรกทอรีทำงานของโปรเซส lighttpd ขณะรัน (มักเป็น `/`) ซึ่งแทบคาดเดาไม่ได้ **แทนที่ 5 บรรทัดนี้ด้วยพาธแบบสัมบูรณ์** ที่เหมาะกับการติดตั้งของคุณ ตัวอย่างเช่น:
> ```lua
> local blocklist_file         = omega_paths.blocklist_file or "/var/lib/lighttpd/waf/magnet-blocklist.txt"
> local waf_rules_dir          = omega_paths.rules_dir or "/var/lib/lighttpd/waf/magnet-rules.d/"
> local alerts_log             = omega_paths.alerts_log or "/var/log/lighttpd/waf-magnet-alerts.log"
> local blocklist_log          = omega_paths.blocklist_log or "/var/log/lighttpd/waf-magnet-blocklist.log"
> local rate_store_file        = omega_paths.rate_store_file or "/var/cache/lighttpd/waf-magnet-rate_store.lua"
> ```
> ก่อนรีสตาร์ต ให้สร้างโฟลเดอร์เหล่านี้ (คำสั่งในขั้นตอนที่ 2 ของ [การนำไปใช้งาน](#การนำไปใช้งาน)) โดยกำหนดสิทธิ์ดังนี้:
>
> | ไฟล์ | สิทธิ์ที่บัญชีของ lighttpd ต้องมี |
> |---|---|
> | `blocklist_file`, `alerts_log`, `blocklist_log`, `rate_store_file` | **เขียน** (ทั้งไฟล์และโฟลเดอร์ที่บรรจุไฟล์) |
> | `waf_rules_dir` (และ `whitelist_paths.txt`) | อ่านอย่างเดียว |
>
> การเขียนที่ล้มเหลวจะ **เงียบ** — สคริปต์ไม่เคยทำให้คำขอเสีย — : การแบนที่ไม่ปรากฏใน `blocklist_file` เป็นอาการเดียวที่เห็นได้ ตรวจสอบด้วย `sudo -u www-data touch /var/lib/lighttpd/waf/magnet-blocklist.txt` (ปรับชื่อบัญชีให้ตรง) หากยูนิต systemd ของ lighttpd จำกัดการเขียน (`ProtectSystem=strict`, `ReadWritePaths=`) ให้เพิ่มโฟลเดอร์เหล่านี้เข้าไป

## ไปป์ไลน์การตัดสินใจ

สคริปต์ทำงานทั้งหมดภายใน `pcall` ระดับบนสุด: ข้อผิดพลาด Lua ที่ไม่คาดคิดทุกกรณีจะถูกบันทึกลงล็อกแล้วตอบกลับ `500` โดยไม่ทำให้โปรเซสของเซิร์ฟเวอร์ล่มเลย ขั้นตอนต่าง ๆ ทำงานตามลำดับนี้ และแต่ละขั้นสามารถหยุดการประมวลผลด้วยการตอบกลับขั้นสุดท้ายได้:

1. **รายการบล็อก** — หาก IP ถูกแบน คำขอจะถูกปฏิเสธ (`451`) เว้นแต่พาธที่ร้องขออยู่ใน whitelist อย่างชัดเจน (เช่น ใช้ส่งหน้าแสดงข้อผิดพลาดเอง)
2. **พาธที่อ่อนไหว** — หากพาธตรงกับรูปแบบที่เฝ้าติดตาม (`.git`, `.env`, `wp-admin`...) จะส่งหน้าคำเตือน HTML กลับไป (`403`) ในครั้งแรก; การกระทำซ้ำภายในกรอบเวลาที่น่าสงสัยจะทำให้ถูกแบน (`451`)
3. **User-Agent ของเครื่องมือสแกน** — หาก User-Agent ตรงกับเครื่องมือสแกน/บอตที่รู้จัก ตอบ `403` ในครั้งแรก และ `451` เมื่อกระทำซ้ำ
4. **การจำกัดอัตราแบบรวม** — หากเกินโควตารวมต่อ IP ตอบ `429`
5. **นโยบาย SearXNG** — สำหรับเส้นทางค้นหาที่รู้จัก: การจำกัดอัตราเฉพาะ (`429`) ตัวป้องกันขนาดของ query string (`414`) ปฏิเสธไบต์ NUL (`451`) แล้วออกทันที (`0`, ดำเนินต่อ) เพื่อไม่ให้การค้นหาที่ชอบธรรมต้องผ่านการตรวจสอบเข้มงวดในขั้นถัดไป
6. **การป้องกันพาธ** — ค้นหา SQLi และ XSS ในพาธที่ถอดรหัสแล้ว (`451` หากตรวจพบ); ค้นหา path traversal (`451`) โดยเจตนา **ไม่** ตรวจจับ command injection ในขั้นนี้ (ดู [ข้อจำกัดที่ทราบ](#ข้อจำกัดที่ทราบและสิ่งที่อยู่นอกขอบเขต))
7. **การป้องกันแบบเบาของ query string** (นอกเส้นทาง SearXNG) — path traversal และไบต์ NUL (`451`)
8. **การตรวจสอบเนื้อหา POST** — เฉพาะเมื่อเปิด `enable_body_inspection` และเมธอดเป็น `POST`: เนื้อหาที่ใหญ่เกินไปจะถูกปฏิเสธทันที (`413`); มิฉะนั้นจะคิดคะแนนสะสมจาก SQLi/XSS/CMDi/traversal ปฏิเสธ (`451`) หากคะแนนถึง `waf_score_threshold` และแบนทันทีหากคะแนนถึง 8 มิฉะนั้นนับเป็นครั้งที่น่าสงสัยธรรมดา
9. **ไม่มีการบล็อก** — คำขอดำเนินต่อตามปกติ (`0`)

## ซิกเนเจอร์ที่ตรวจจับ

รูปแบบสี่ตระกูล (`patterns`) แต่ละรายการเป็นสตริง (แยกตัวพิมพ์ใหญ่-เล็ก) หรือเป็นตาราง `{ pat = "motif", ci = true }` (ไม่แยกตัวพิมพ์ใหญ่-เล็ก):

- **`sqli_body`**: `UNION SELECT`, `SELECT ... FROM`, `INSERT INTO`, `DROP TABLE`, `OR 1=1`, `' OR '1'='1`, `SLEEP(...)`, `BENCHMARK(...)` การฉีดคำสั่ง SQL ผ่านเครื่องหมายอัฒภาค (`; DROP`, `; ALTER`, `; EXEC`, `; SHUTDOWN`)
- **`xss_body`**: แท็ก `<script>`, `<iframe>` แอตทริบิวต์ `on*=` (ตัวจัดการเหตุการณ์), `javascript:`, `eval(...)`, `document.cookie`, `svg/onload`
- **`cmdi_body`**: การต่อคำสั่งเชลล์ (`; ls`, `; id`, `; whoami`, `; cat`, `; wget`, `; curl`, `; nc`, `; bash`, `; sh`, `; python` และรูปแบบที่ใช้ `|`) การแทนที่คำสั่ง (`` `...` ``, `$(...)`) แท็ก PHP (`<?php`) และฟังก์ชันสั่งรันคำสั่ง (`system(`, `exec(`, `passthru(`)
- **`path_traversal`**: `../`, `..\`, `/proc/self/`, `etc/passwd`, `etc/shadow`, `file://`, `php://filter`

และรายการเฉพาะของ **User-Agent ของเครื่องมือสแกน/บอต** (`patterns_scanner_ua`): `masscan`, `sqlmap`, `nmap`, `nikto`, `dirbuster`, `wfuzz`, `zgrab`, `python-requests`, `go-http-client`, crawler ด้าน SEO (`ahrefsbot`, `mj12bot`, `semrushbot`, `blexbot`, `dotbot`, `spbot`, `yandexbot`, `sogoubot`) และรูปแบบทั่วไป (`spider`, `crawler`, `bot`, `scraper`, `facebookexternalhit`, `lwp::simple`)

การถอดรหัส URL ถูกใช้แบบเวียนเกิด (สูงสุด 5 ระดับบนพาธ และ 2 ระดับบน query string) ก่อนการตรวจสอบ เพื่อจับเพย์โหลดที่ถูกเข้ารหัสซ้ำ

## พาธที่อ่อนไหวที่เฝ้าติดตาม

รูปแบบที่ตรวจสอบบนพาธที่ถอดรหัสแล้ว: `.env`, `.git`, `.svn`, `.hg`, `.bzr`, `composer.json`/`composer.lock`, `vendor/`, `phpunit/`, `phpmyadmin`/`pma`/`adminer.php`, `wp-admin`/`wp-login.php`, `/server-status`, `.DS_Store`

สำหรับทุกการจับคู่ สคริปต์จะพยายามตรวจว่ามีทรัพยากรจริงอยู่ที่พาธนั้นหรือไม่ (ผ่าน `lighty.stat` และใช้ `lighty.c.stat` สำรองเพื่อความเข้ากันได้) แล้วระบุไว้ในหน้าคำเตือนและในล็อก — มีประโยชน์ในการแยกแยะการสแกนแบบสุ่มออกจากพาธที่มีอยู่จริงบนเซิร์ฟเวอร์

## การจำกัดอัตราและการยกระดับ

ตัวจำกัดอัตราอิสระสองตัว อาศัยตัวนับในหน่วยความจำที่บันทึกถาวรลงดิสก์ (กรอบเวลาเลื่อนแบบง่าย ไม่ใช่กรอบเวลาเลื่อนที่แม่นยำระดับวินาที):

- **แบบรวม**: คีย์ `g:<ip>`, `global_rate_max_req` คำขอต่อ `global_rate_window` วินาที ครอบคลุมทุกเส้นทาง
- **SearXNG**: คีย์ `sx:<ip>`, `searx_rate_max_req` คำขอต่อ `searx_rate_window` วินาที เฉพาะบนเส้นทางค้นหาที่รู้จัก

การยกระดับเป็นขั้น (`record_suspicious_hit`) เป็นกลไกที่แยกจากการจำกัดอัตรา: การตรวจจับที่ไม่ร้ายแรงแต่ละครั้ง (พาธที่อ่อนไหวที่ไม่ใช่การกระทำซ้ำ, User-Agent ของเครื่องมือสแกน, การตรวจพบเล็กน้อยในเนื้อหา POST) จะเพิ่มตัวนับต่อ IP (คีย์ `susp:<ip>`) ในกรอบเวลา `suspicious_window` วินาที เมื่อครบ `suspicious_threshold` ครั้งภายในกรอบเวลานี้ IP จะถูกเพิ่มเข้ารายการบล็อกถาวร — หลีกเลี่ยงการแบนทันทีจากผลบวกลวงเพียงครั้งเดียว ในขณะที่ยังแบนผู้กระทำซ้ำได้

**เครือข่ายที่ไม่เคยถูกแบน**: ที่อยู่ใน `never_auto_block` (โฮสต์ในเครื่อง, Tailscale `100.64.0.0/10`, เครือข่ายในพื้นที่ IPv4/IPv6 รวมถึงรูปแบบ IPv4-mapped IPv6) จะไม่เคยทำให้เกิดการยกระดับหรือการเพิ่มเข้ารายการบล็อก; การแบนที่ถูกข้ามจะถูกบันทึกด้วยบรรทัด `BAN EVITE` ใน `blocklist_log` (ไม่ใช่ `AJOUT BLOCKLIST` ซึ่ง omega-jail อ่าน) การเปรียบเทียบ CIDR ใช้ Lua แบบพกพาได้ ตั้งแต่ 5.1 ถึง 5.5 และ LuaJIT

**โหมด log-only ของ omega-serv**: เมื่อ WAF ของ omega-serv อยู่ในโหมด `log-only` สคริปต์จะไม่ตั้งการแบนใด ๆ (ไม่เขียนรายการบล็อก ไม่มีบรรทัด `AJOUT BLOCKLIST` จึงไม่มีการแบนระดับเครือข่ายโดย fail2ban) โดยมีบรรทัด `BAN EVITE` บันทึกไว้ หากเขียนรายการบล็อกไม่ได้ จะใช้บรรทัด `ECHEC BLOCKLIST` แทน `AJOUT BLOCKLIST`

## การจัดเก็บถาวร

| ไฟล์ | เนื้อหา | รูปแบบ |
|---|---|---|
| `blocklist_file` | หนึ่ง IP ที่ถูกแบนต่อบรรทัด นำหน้าด้วยความคิดเห็นที่มีเวลากำกับ (`# date - raison`) | ข้อความธรรมดา |
| `waf_rules_dir/whitelist_paths.txt` | หนึ่งรูปแบบ Lua (`string.match`) ต่อบรรทัด เป็นพาธที่อนุญาตเสมอแม้สำหรับ IP ที่ถูกแบน | ข้อความธรรมดา |
| `rate_store_file` | ตัวนับการจำกัดอัตราและการกระทำซ้ำ (`{ count = N, first = timestamp }` ต่อคีย์) | ตาราง Lua ที่ซีเรียลไลซ์แล้ว (`return { ... }` อ่านกลับผ่าน `load()`) |
| `alerts_log` | หนึ่งบรรทัดต่อการตรวจจับ/การปฏิเสธ | ข้อความที่อ่านได้ หรือ JSON หาก `use_json_logs = true` |
| `blocklist_log` | หนึ่งบรรทัดต่อการเพิ่มเข้ารายการบล็อก | ข้อความที่อ่านได้ |

ไฟล์การจำกัดอัตราไม่เคยถูกเขียนใหม่ทุกคำขอ (เขียนอย่างมากทุก 300 วินาที ระหว่างการล้างข้อมูลตามรอบ) เพื่อหลีกเลี่ยงค่าใช้จ่าย I/O ที่ไม่สมเหตุสมผล รายการบล็อกและ whitelist ถูกแคชไว้ในหน่วยความจำและอ่านใหม่อย่างมากทุก `blocklist_refresh_interval`/`whitelist_refresh_interval` วินาที — การเพิ่มที่สคริปต์เป็นผู้ทำเองจะอัปเดตแคชทันทีโดยไม่ต้องรอช่วงเวลานี้

## รหัสตอบกลับ HTTP ที่ส่งออก

| รหัส | ความหมาย | เงื่อนไขที่ทำให้เกิด |
|---|---|---|
| `0` | ดำเนินการประมวลผลตามปกติต่อ (แบบแผนของ `mod_magnet`) | ไม่มีการตรวจจับ |
| `403` | ปฏิเสธการเข้าถึง คำเตือนครั้งแรก | ตรวจพบพาธที่อ่อนไหว (ครั้งแรก), User-Agent ของเครื่องมือสแกน (ครั้งแรก) |
| `413` | เนื้อหามีขนาดใหญ่เกินไป | เนื้อหา POST เกิน `body_max_inspect` |
| `414` | URI ยาวเกินไป | query string ของ SearXNG เกิน `searx_max_query_len` |
| `429` | คำขอมากเกินไป | เกินการจำกัดอัตราแบบรวมหรือของ SearXNG |
| `451` | ไม่พร้อมให้บริการด้วยเหตุผลทางกฎหมาย (ใช้ที่นี่เป็นรหัสการแบน) | IP ถูกแบนอยู่แล้ว, การกระทำซ้ำหลังการยกระดับ, ตรวจพบ SQLi/XSS/traversal ในพาธหรือ query string, ไบต์ NUL, คะแนน POST ≥ เกณฑ์ |
| `500` | ข้อผิดพลาดภายใน | ข้อยกเว้น Lua ที่ไม่คาดคิด (ถูกดักจับโดย `pcall` ระดับบนสุด) |

## ความเข้ากันได้

สคริปต์ทำงานได้ใน **สองบริบท** โดยไม่ต้องแก้ไขใด ๆ:

- **lighttpd แบบเนทีฟ**: `lighty.env`/`lighty.header`/`lighty.content`/`lighty.stat` เป็น API เนทีฟของโมดูล `mod_magnet` พาธการกำหนดค่าทั้ง 5 ใช้ค่าเริ่มต้นที่กำหนดตายตัวโดยตรง
- **omega-serv** (`infrastructure/waf/lua_waf_adapter.py`): สะพาน Python-Lua (`lupa`) จำลองสัญญา `lighty.*` เดียวกันได้อย่างถูกต้อง พร้อมรันไทม์ Lua แบบ **ถาวร** ระหว่างคำขอ (แคชตามเวลาและการจำกัดอัตราจึงคงอยู่จากคำขอหนึ่งไปอีกคำขอได้อย่างถูกต้อง เช่นเดียวกับใน lighttpd) ตารางส่วนกลาง `omega_magnet_paths` ถูกฉีดก่อนการทำงานจากการกำหนดค่าของหน้าจอ WAF Magnet เพื่อให้ 5 พาธชี้ไปยังตำแหน่งที่เลือกไว้ในอินเทอร์เฟซแทนค่าที่กำหนดตายตัว

ไม่มีความแตกต่างของตรรกะทางธุรกิจระหว่างสองบริบท — มีเพียงที่มาของพาธการกำหนดค่าทั้ง 5 ที่เปลี่ยนไป

### สิ่งที่ไม่เข้ากันได้ตามสภาพเดิม

สคริปต์พึ่งพาสัญญา `lighty.*` (API เนทีฟของ `mod_magnet`) ทั้งหมด — จึง **ไม่** ทำงานตามสภาพเดิมบนเซิร์ฟเวอร์อื่น แม้เซิร์ฟเวอร์นั้นจะมีการเขียนสคริปต์ Lua ในรูปแบบใดรูปแบบหนึ่งก็ตาม:

- **Apache** (`mod_lua`): API ต่างกัน อิงกับออบเจกต์คำขอ `r` (`r.method`, `r.uri`, `r.headers_in`, `r:puts(...)`) — ไม่มีการเรียก `lighty.*` ใดที่จะทำงานได้
- **nginx** (`lua-nginx-module` / OpenResty): API ต่างกัน (`ngx.var`, `ngx.req`, `ngx.header`, `ngx.exit()`) พร้อมโมเดลเฟสการทำงาน (`access_by_lua`, `content_by_lua`...) ที่ต่างจากการคืนรหัสแบบง่ายของ `mod_magnet`
- **Traefik**: ไม่มีการเขียนสคริปต์ Lua แบบเนทีฟ (เขียนด้วย Go) — มีเพียงปลั๊กอิน Go (Yaegi) ที่สามารถรันตรรกะที่กำหนดเองได้ ไม่ใช่ Lua โดยตรงเลย
- **Caddy**: ไม่มีโมดูล Lua อย่างเป็นทางการ — ต้องใช้ปลั๊กอินของบุคคลที่สามที่คอมไพล์ผ่าน `xcaddy` ไม่มีสิ่งที่เทียบเท่าให้ใช้แบบเนทีฟ

การทำให้สคริปต์นี้เข้ากันได้กับเซิร์ฟเวอร์ใดเซิร์ฟเวอร์หนึ่งข้างต้นจะต้องเขียนสะพานความเข้ากันได้เฉพาะที่แปลง API เนทีฟของเซิร์ฟเวอร์นั้นไปเป็น `lighty.*` (เหมือนกับที่ `lua_waf_adapter.py` ทำให้ omega-serv) — เป็นงานวิศวกรรมเต็มรูปแบบ ไม่ใช่แค่การปรับการกำหนดค่า

## การปรับแต่ง

- **ปรับใช้กับแอปพลิเคชันอื่นนอกจาก SearXNG**: แก้ไข `is_searxng_path()` (รายการพาธ) และหากจำเป็น ให้ลบส่วนที่ 3 ของไปป์ไลน์ (นโยบายเฉพาะ) ออกทั้งหมด หากแอปพลิเคชันที่ป้องกันไม่ต้องการการจัดการการค้นหาแบบแยกต่างหาก
- **เพิ่มพาธที่อนุญาตเสมอ**: แก้ไข `waf_rules_dir/whitelist_paths.txt` (หนึ่งรูปแบบ Lua ต่อบรรทัด) หรือเพิ่มข้อยกเว้นแบบกำหนดตายตัวใน `is_whitelisted_path()`
- **ปรับความเข้มงวด**: `waf_score_threshold` (เกณฑ์การปฏิเสธ POST), `suspicious_threshold`/`suspicious_window` (ความเร็วในการยกระดับไปสู่การแบนถาวร), `global_rate_max_req`/`global_rate_window` (การจำกัดอัตราทั่วไป)
- **สลับล็อกเป็น JSON** (สำหรับนำเข้า SIEM/log shipper): `use_json_logs = true`
- **ปิดระบบย่อยหนึ่งโดยไม่กระทบส่วนอื่น**: `enable_body_inspection`, `enable_rate_limit`, `enable_auto_block` เป็นอิสระต่อกัน

## ข้อจำกัดที่ทราบและสิ่งที่อยู่นอกขอบเขต

- **ไม่ตรวจจับ CMDi บนพาธของ URL**: เป็นการเลือกโดยเจตนาเพื่อหลีกเลี่ยงผลบวกลวงกับพาธที่มี `.php` (ซึ่งจะถูกสับสนกับ `<?php` หากการตรวจจับ CMDi รวมแท็ก PHP บนส่วนนี้ด้วย) การตรวจจับ CMDi ยังคงทำงานบนเนื้อหา POST
- **ซิกเนเจอร์ใช้การจับคู่รูปแบบของ Lua ไม่ใช่เอนจิน PCRE ที่แท้จริง**: รูปแบบการโจมตีที่ไม่อยู่ในรูปแบบที่ระบุไว้จะตรวจจับไม่ได้ — สคริปต์นี้ไม่ได้แทนที่ WAF ที่อาศัยชุดกฎแบบครอบคลุม (เช่น CRS ของ ModSecurity)
- **ไม่แยกวิเคราะห์ multipart/form-data**: เพย์โหลดอันตรายที่ห่อไว้ในฟิลด์ฟอร์มแบบ multipart อาจหลุดรอดการตรวจสอบได้ หากรูปแบบไม่ตรงกับสตรีมดิบที่ยังไม่ถอดรหัส
- **ไม่คลายการบีบอัด gzip ของเนื้อหา**: เนื้อหาที่บีบอัดจะไม่ถูกตรวจสอบในรูปข้อความปกติ
- **การจำกัดอัตราแบบประมาณ**: กรอบเวลาเลื่อนแบบง่าย (รีเซ็ตทั้งหมดเมื่อเกินกรอบเวลา) ไม่ใช่อัลกอริทึมกรอบเวลาเลื่อนที่แม่นยำ (sliding log/token bucket)
- **ไม่มีอินเทอร์เฟซสำหรับเฝ้าดู**: การสังเกตทั้งหมดต้องอ่านไฟล์ล็อกและรายการบล็อกโดยตรง

## การแก้ไขปัญหา

- **สคริปต์ดูเหมือนไม่เคยทำงาน**: ตรวจสอบว่าโหลด `mod_magnet` แล้วจริง (lighttpd) หรือได้ติดตั้งส่วนเสริม `magnet` และเปิดใช้งาน WAF Magnet แล้ว (omega-serv); การรีโหลดการกำหนดค่าไม่เคยเพียงพอที่จะโหลดสคริปต์ Lua ที่แก้ไขแล้ว ต้องรีสตาร์ตเต็มรูปแบบในทั้งสองกรณี
- **ตัวนับการจำกัดอัตราดูเหมือนรีเซ็ตทุกคำขอ**: เป็นอาการของรันไทม์ Lua ที่ไม่ถาวรระหว่างคำขอ (สคริปต์เริ่มต้นใหม่ด้วย `rate_store` ว่างทุกครั้งที่ทำงาน) — ภายใต้ omega-serv ให้ตรวจสอบว่าหน้าจอ WAF Magnet แสดงว่ามีรันไทม์ถาวรทำงานอยู่
- **IP ที่ชอบธรรมถูกแบน**: ดู `blocklist_log` และ `alerts_log` เพื่อระบุกฎที่ถูกกระตุ้น ปรับรูปแบบหรือเกณฑ์ที่เกี่ยวข้อง แล้วลบบรรทัดของ IP นั้นออกจาก `blocklist_file` (แคชในหน่วยความจำจะอัปเดตในการโหลดใหม่ครั้งถัดไป อย่างช้าภายใน `blocklist_refresh_interval` วินาทีหลังจากแก้ไขไฟล์)
- **การค้นหา SearXNG ที่ชอบธรรมถูกบล็อก**: ตรวจสอบ `is_searxng_path()` (พาธที่ไม่รู้จัก) ก่อนปรับเกณฑ์การจำกัดอัตราเฉพาะ
- **`pip install -e ".[magnet]"` ล้มเหลวด้วย `pip: command not found` หรือ `externally-managed-environment`**: คำสั่งถูกพิมพ์นอก `.venv` ของ omega-serv (บางดิสทริบิวชัน โดยเฉพาะ Arch Linux ไม่มี `pip` ของระบบที่ใช้งานได้โดยตรง) ให้ใช้ `.venv/bin/python -m pip install -e ".[magnet]"` จากไดเรกทอรีของ omega-serv — ทำงานได้โดยไม่ขึ้นกับว่ามี `pip` อยู่บน `PATH` ของระบบหรือไม่ (ดู [การติดตั้งส่วนเสริม `magnet` ของ omega-serv](#การติดตั้งส่วนเสริม-magnet-ของ-omega-serv))
